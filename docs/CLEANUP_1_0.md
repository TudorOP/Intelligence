# Cleanup before 1.0 implementation

The prerequisite pass shares the pure provider catalog between native inference and renderer controls, and extracts the existing profile inputs into one reusable form. It removes the duplicated provider definitions and inline profile form; connection transport, validation and saved values retain their existing behavior. Model-setting spacing is tightened and Settings uses more of the available height after the fixture exposed overflowing content at 1080p, including API-key controls; short windows retain internal scrolling.

Intentional differences remain: renderer visibility is not native authority; Tasks assignment is not Matrix integration; global settings are not per-profile restrictions; MCP setup is not ordinary action approval. No speculative replacement framework, dependency changes, artwork replacement or schema renumbering was introduced. Dead code is removed only when proven unused; optional engines and migration paths remain intact.

The 0.94 baseline passes all 207 enabled backend tests, TypeScript/production build and isolated desktop smoke. Its JavaScript output totals 1,391,869 bytes. A reproducible performance fixture lives in scripts/verify-performance.mjs and writes ignored results under .test-data. Baseline startup was 954 ms; idle process CPU was below 0.1% per measured process. Hidden-window Playwright Settings clicks take roughly 2 seconds after the first click, so these wall-clock values include automation/frame waiting and are not direct user-visible latency measurements. Working-set measurements include browser/GPU/utility/renderer processes and normal warm-up; compare repeated runs on the same host before drawing conclusions.

The extracted-form/catalog build totals 1,391,965 JavaScript bytes (+96 bytes). Its 207 backend tests and desktop smoke pass. The first resource sample was taken alongside other fixtures, so its startup timing is not a fair regression comparison. The final 1.0 acceptance records the applicable Settings, resource and full-app visual checks separately in docs/VERIFICATION.md.

The completed cleanup also passes the Settings fixture: 27 captures covering ten settings sections, local/API variants, shorter/larger/scaled windows and Romanian. Profile/model captures were visually inspected. This verified foundation precedes feature implementation; it does not claim the later 1.0 behavior is already present.
