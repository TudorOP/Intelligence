# Projects and file tools

Projects use created or selected real directories. Browsing is lazy/bounded; text reads/edits report revisions and differences, and unsupported/binary files give visible feedback. Source paths stay within authorized project boundaries.

Writes/moves/Trash require edit access and the native approval policy. Revisions detect external changes; host reads outside a project require approval. Project Trash retains the directory's files, while project file Trash records recoverable bytes/metadata.

App data should be accessed through structured tools. Host terminal permissions are separate and may be broader than project-resource grants. Never send administrator passwords in chat.
