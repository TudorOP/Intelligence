# Intelligence — interface and interaction

Studio is a calm desktop shell with a shallow sidebar, a main canvas and an optional resizable global assistant. Target 1920×1080; larger displays gain useful space and shorter windows retain internal scrolling. Keep drafts, selections and assistant conversations across navigation.

Themes change palette and artwork, not task meaning or permission boundaries. Festive uses evergreen/burgundy/champagne gold; Tech uses charcoal/emerald wireframes; Astral uses midnight indigo/brass celestial imagery; Marble uses ivory stone/brushed gold. Original six themes remain available. Solid controls and reading surfaces protect text contrast.

Settings → Look & feel groups theme, display and still background artwork. Built-in artwork or a bounded local image is separate from the palette. Strength controls visibility and 0–24 px blur controls softness; zero adds no blur. Effects apply only to the decorative layer. Animated backgrounds and their controls are removed and explicitly deferred. Interface transitions retain reduced-motion support. The compact 32 px Pause/Resume AI button uses matching typography/symbols and localized help; it gates automatic tasks/memory while keeping foreground chat available. Search provider names are concise; connection descriptions disclose the actual SearXNG route where applicable.

Main Chat and the assistant share reply, Thinking, composer and tool geometry. Branch/Read aloud use equal symbolic buttons with localized hover/focus help. Stop retains the same dimensions. Uninterrupted tool activity is one expandable chronological group with visible failure counts; stored transport history and native approvals are unchanged.

Collection menus have visible and right-click entry points, viewport-safe placement, Escape/focus behavior and keyboard alternatives to drag/drop. Revisions protect edits and conflicting changes remain visible. Trash is recoverable; permanent deletion requires an explicit scope.

Access inherits from parents, with child exceptions. Read/edit access, task assignment, model context and host-terminal approvals are separate concepts. The agent cannot change its own grants or infer authorization from document/tool text.

Use existing switch/checkbox semantics, readable controls, reduced motion and English/Romanian help. See docs/APPEARANCE.md and docs/VERIFICATION.md for implementation/acceptance.

Main Chat and the assistant use matching 32 px native model/approval dropdowns. The composer order is model, image attachment, Thinking, automatic TTS, symbolic microphone, then approvals; controls wrap in that order within the compact panel. Dictation retains localized labels and selected listening state. Board lists have a dedicated drag handle, insertion markers and Move list left/right menu alternatives. Reordering changes ordering only, with revision conflicts kept visible.

Memory distinguishes conversation summaries, extracted facts and explicitly saved entries. Counts explain the stored inventory and review queue. Expand Stored details & sources for recorded source-message excerpts, origin/model/fact details and current native resource access. Excerpts are labeled separately from stored memory, and original conversations remain available. Older generic summaries retain their text and gain a source-inspection hint; new consolidation omits matching placeholders. Search on this screen ranks saved memories, while general agent recall can also retrieve authorized notes.

Expanded task agent controls, assignment/runtime controls and Agent Report depend on native effective card access. Parent inheritance, card exceptions and the global Tasks access switch apply. Run now additionally requires native edit access and assignment. Inaccessible cards keep their content, completion criteria, schedule and linked items without the agent section.

Model & providers has an expandable Connected providers list with individual Use / configure and Disconnect controls. Connections preserve separate addresses/models and OS-protected credentials; disconnect removes every saved key for that provider and stops its runs. Model pickers group choices by provider, including identically named models. Conversation/branch choices do not change other chats. No automatic provider fallback occurs. General tool rounds are configurable from 1 to 256, default 12, with separate Matrix/report budgets.

Both chat surfaces keep Stop available and add Steer while responding. Enter submits a text correction; Shift+Enter inserts a line break. Pending corrections are visible above the composer. Corrections apply between model/tool steps, retain completed results, cancel unstarted batch calls and decline pending native approvals. They do not interrupt an already executing tool or change grants. Stopped corrections remain in the transcript for the next response; images attach after completion. Matrix replies retain the existing native task runner. This boundary behavior follows the steering pattern described in [OpenAI’s Codex guidance](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan).

Tasks is the Kanban board/list/card screen for user work and optional agent assignments. Cognition Matrix is the separate agent-only matrix-list/matrix-task queue. Native discovery carries section/purpose and current assignment/eligibility; titles never determine which section an entity belongs to. Tool routing is documented in docs/TOOL_ROUTING.md.

Chapter overview offers Saved chapter content only when existing body text is present. The read-only Markdown card supports checklists, tables, code and internal scrolling. Create note from this content preserves the chapter, creates a real child note, rejects stale revisions and reuses an existing copy of that revision. New agent document writes target notes/files, not containers. Durable entity changes update the workspace while chat continues; Stop never rolls back completed writes.

Agents can configure/connect/disconnect requested MCP servers through the shared native approval card, showing the exact executable/arguments or HTTP target and effect before any setup mutation. MCP setup always asks for this native review, including Full Access. Configuration success, connection, discovery and capability verification remain distinct. The built-in MCP server setup skill is visible in Skills and respects user disable/Trash and profile restrictions. OAuth/secret entry is outside the setup tool; existing Connections remains the user's management surface.
